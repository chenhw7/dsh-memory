DEEPSEEK HARNESS · 长期记忆插件

重启之后，它还记得。

Cairn 是给 DeepSeek Harness 的持久化跨会话记忆——一条命令安装 · 九个模型工具 · 五种注入模式。事实、偏好、约定与踩坑跨会话存活：每个新会话一开始，智能体就带着上一次的经验。

WHY · 为什么需要它

会话一结束，一切归零

默认情况下，智能体没有跨会话的记忆——你上周说过的、昨天踩过的，今天全部重来。

WITHOUT MEMORY · 没有记忆

每个会话都从零开始

「以后都用 pnpm」说过就忘；同一个构建坑掉进去第二次；上次会验证过的结论，今天全凭印象复述。上下文越堆越长，真正重要的事反而要反复交代。

偏好反复交代踩坑重蹈结论靠记忆
WITH CAIRN · 装上 Cairn

说过一次，就沉淀一次

值得记的信号被自动提取、安全扫描、审计入库；下个会话开场，相关的记忆就以索引形式在场，需要全文时按需召回。使用即保鲜，遗忘有规则。

四大能力

01 · 持久存储

双后端 KV 存储，全量审计

JSON（宿主存储域）或 SQLite（node:sqlite，零额外依赖）两种后端，迁移一次完成；跨进程单写者检测防止并发覆盖。entries / audit / suggestions / meta 四张表，每次变更都有来源与审计。卸载插件，记忆不丢。

02 · 智能检索

零依赖 BM25，中文是一等公民

手写的 Okapi BM25：拉丁词保守词干收敛词形，中文产出单字一元 + 相邻二元——「记忆」不再命中所有含「记」的条目。三层作用域（global / project / user），summary 与正文同入索引，置顶条目优先浮出。

03 · 自动学习

提取、整合、冲突取代

三类信号（明确意图 / 用户纠正 / 连续踩坑后成功）触发 LLM 提取；新旧条目先经 IDF 加权预筛，再一次批量整合裁决——重复合并、过期冲突直接取代并留下 supersededBy 标注。可选人审队列：模型只提议，裁决权在你。

HOW · 它怎么工作

三步闭环：沉淀 → 存取 → 注入

会话中 · 沉淀

三类信号流过零 LLM 成本的累加器：明确意图（「记住 / 以后都」）、用户纠正（「不对，其实是」）、连续踩坑后的成功。攒够阈值（默认 10），才触发一次 LLM 提取。

落库 · 存取

每条写入先过 37 条安全扫描规则，再追加审计；与既有条目去重整合，重复的合并、过时的取代。BM25 索引随写随就绪，命中即刷新保鲜时间戳。

下个会话 · 注入

会话创建时冻结快照（默认 index 索引模式），模型看见「存了什么」，用 memory_get 按需取全文；步级还可自动召回相关记忆，全部带 token 成本标注。

跟着一条记忆走完它的一生 →
TRUST · 安全与控制

每一条记忆，都过闸、都留痕

记忆会在未来被重新读进上下文——它本身就是攻击面，所以必须双面设防。

WRITE + READ · 双防线

写入扫描，读取脱敏

写入时 37 条规则拦截（密钥 16 · 提示词注入 17 含 8 条中文 · 外泄 4），永不落库；读取时每个注入面重新脱敏，漏网内容渲染为 [BLOCKED: …]。原文保留，静默删除只会掩盖攻击。

AUDIT · 全量审计

谁写的、何时写的，永远可查

每次变更追加一条审计：操作、来源（tool / review / flush / ui / janitor）、内容预览，200 条滚动、单调 seq。

GUARD · 危险操作有闸

批量遗忘不会失控

memory_forget 需要显式 confirm: true；批量删除有上限、置顶条目豁免并报告、每条删除独立审计。

HUMAN · 人审一票否决

模型提议，人裁决

打开写入前人工确认：所有提取与工具写入降级为提议，被反复观察的提议自动置顶；对既有条目的修改，采纳前绝不触碰原文。

REMOTE · 远程写默认拒绝

宽信任域不放大权限

浏览器端管理默认只读，写操作需部署级显式开启——信任的是传输面，不是存储面。

PROMPT · 提示词防御

记忆是上下文，不是指令

存储内容里的伪造围栏闭合符在渲染时被中和；每个注入面都声明：当前用户请求、仓库文件与工具输出永远优先于记忆。

FIT · 适合这样用

个人与团队的长期资产

跨会话的个人偏好与工作习惯；项目的团队约定与提交规范；调试中验证过的踩坑与解法；长期迭代中沉淀的工程判断。它面向「帮智能体积累经验」，不是通用知识库。

LIMITS · 已知限制

诚实说在前面

检索是纯词法的：BM25 不做语义向量，换一种说法的查询不会命中（同义改写靠 summary 入索引兜底）；提取质量跟随会话模型，不引入额外按键；宿主 DeepSeek Harness 处于 alpha 渠道（0.1.2-alpha），插件随之演进；远程管理面仅受信任主机保护，写操作默认关闭。
