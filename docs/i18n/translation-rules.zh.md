# 翻译规则

[English](translation-rules.md) | 中文

如何撰写或更新双语对的中文侧(译入英文时同样适用,方向相反)。[配对契约](README.zh.md)负责范围与 sidecar;本文件负责忠实性、结构与排版。

## 忠实性

- **说的是同一件事,不多也不少。** 一侧的每个命题都要出现在另一侧:主语、动作、条件、模态(`must` / `should` / `may` / `never`)、数字、异常与否定性保证全部保留。翻译不是改写:不要通过默默选择一种语义来消解歧义——保留歧义,或先修源文。
- **对对侧做最小修补。** 更新只改被编辑触及的段落,保留其余部分的既有评审措辞。为一段话而整篇重译,等于丢掉此前所有评审。
- **不悄悄"改进"。** 翻译时发现的更清晰句子属于源侧;先改源侧,再镜像。以"更好措辞"为名的两侧内容分歧是违约,不是帮忙。

## 结构

- 标题层级、顺序、列表种类、有序列表起始号、项数、表格行列数一一对齐。
- **代码块逐字节一致**,注释在内。修一处代码注释,把修好的围栏复制进两侧;两侧各自"流畅地"翻译同一围栏注释,同样是违反配对契约。
- 指向现行双语语料的相对文档链接,英文侧用 `.md`、中文侧用 `.zh.md`,query/fragment 后缀完全一致。语料外的链接两侧均保留原路径。
- 两侧均为"一段一行",用编辑器软换行。

## 术语

- 翻译**前**加载 [terminology.md](terminology.md),而不是遇到拿不准的词再查——注意不到的术语才是漂移的术语。
- 表内术语双向严格按表渲染。首次出现遵循术语表的首现指引;未收录术语需有可引用的中文开源/厂商先例,否则保留英文并加首现注释(`BM25(一种词频相关性排序算法)` 式),确认后同一次变更中把它加入术语表。
- 已收录术语禁止现场发明译法。

## 排版

- 中文正文用全角标点;代码 span、标识符、URL 内保持半角。
- 中文字符与拉丁词、数字之间加半角空格(`BM25 检索`、`3 个作用域`);中文与全角标点之间不加。
- 保留强调、`MUST` 级模态与链接文本语义;翻译更新不做装饰性重排。

## 操作规则

1. 读源侧语义单元,以母语技术作者的方式重述,再逐子句核对:无添加、无遗漏、术语按表、代码 span 原样。
2. 对照完成后,脱离源文件单独通读译文,重写"只有脱离源文才看得出别扭"的措辞。
3. 两侧确认一致后重录 sidecar(见 [README.zh.md](README.zh.md#手工执行契约))。
4. 源侧本身有错时先修源侧再镜像——译者不是单侧语言的"可擅自修订者"。
