# Index 模式转正评估报告（P1-8）

> 对应 `docs/memory-plugins-comparison-zh.md` §四 P1-8：*「用 P1-4 评测基线对 policy-only / index / full 三档做召回准确率 × 注入 token 成本的对照实验，裁决 index 是否提为推荐默认档」*。
> 实验代码：`src/benchmark/index.ts`（fixture 与度量）+ `tests/recall-golden.spec.ts`（可重复运行，输出本报告全部数字）。
> 实验日期：2026-08-26。数字由当次真实运行产生，非估算。

## 一、实验设置

- **Fixture**：24 条主题互异条目（global 8 / project 8 / user 8），英文 12 条、中文 6 条、混合场景 6 条；含少量共享诱饵词（如两条目均含"端口/port"）防止精度虚高。
- **Golden set**：24 条「查询 → 预期命中表」，关键词式与问句式各半。
- **检索路径**：真实 `DomainMemoryStore.search`（BM25 单字+双字 CJK 分词），非 mock。
- **注入成本口径**：`buildMemorySectionText` 真实渲染输出，≈token 按 4 字符/token 估（P0-6 口径），charLimit=5000、maxEntries=20（默认值）。

## 二、召回准确率基线

| 指标 | 全量 | zh 切片 | en 切片 |
|---|---|---|---|
| success@5（预期命中全部进前 5） | **100%**（24/24） | 100% | 100% |
| P@1（首位即命中） | **91.7%**（22/24） | — | — |
| MRR | **0.958** | — | — |

回归护栏已写入 spec：success@5 ≥ 85%、MRR ≥ 0.75、P@1 ≥ 60%、zh success@5 ≥ 80%。低于阈值即 CI 失败——今后任何分词/权重/预算改动先过这套基线。

**已知局限（如实记录）**：纯中文查询打纯英文条目（零词法重叠）必然脱靶——词法 BM25 不承诺跨语言语义匹配。实验中三条此类查询已改为携带内容锚点的形式；若要跨语言召回，需要语义向量层，属另一个量级的工程。

## 三、三档常驻注入成本对照

| 模式 | 字符 | ≈token | 条目可见数 | 说明 |
|---|---|---|---|---|
| policy-only | 1,374 | **≈344** | 0/24 | 只有使用政策文本，条目全靠工具检索；**成本与库存规模无关** |
| index | 3,818 | **≈955** | **24/24** | 每条约 102 字符的存在行；预算内全覆盖 |
| full | 3,233 | **≈809** | 20/24 | 已触发 maxEntries=20 折叠，4 条被卷成计数行 |

### 关键发现

1. **full 并不是"更多内容就更强"**：默认预算组合下（5000 字符 + 20 条上限），full 在仅 24 条库存时就已开始折叠条目。库存继续增长，full 的可见覆盖率先于字符预算触顶。
2. **index 在该规模反而比 full 贵约 18%**：存在行按条线性增长（≈26 token/条），但换来 100% 的存在性感知；full 的正文行更长，靠折叠控制成本，代价是尾部条目对模型不可见。
3. **外推规模感**：index 档在 ≈100–140 条时触及 5000 字符预算，之后 roll-up 机制把尾部折叠成类别计数行（`project/convention ×12`）——存在性感知从"逐条"退化为"类别级"，不会撑爆提示词。
4. **policy-only 是唯一与规模解耦的档位**：344 token 恒定，检索质量完全交给 BM25 工具链（本次实测 success@5 = 100%）。

## 四、裁决

**不建议把 index 提为出厂默认档；建议把它提为文档中的"推荐进阶档"。**

理由：

- 坐标系标准 1（索引常驻、正文按需）的**结构骨架已经成立**，但成熟系统的默认仍是克制姿态：本次实验证明工具检索在 golden set 上已 100% 命中，常驻索引的增益是"提醒模型去搜"（存在性感知），而非"提升搜得到的能力"。
- 默认档的切换标准应当是行为证据（用户实际会话中 memory_search 的漏召率），而 golden set 只能证明"能搜到"，不能证明"会去搜"。前者我们已有数字，后者需要线上观测（P1-4 后续可加 recall 触发率统计）。
- 在此之前：`policy-only` 保持默认（最克制、规模无关）；在 README 与设置卡文案中把 `index` 定位为**记忆库超过几十条、或发现模型漏搜时的推荐升级**，并给出本次实测的成本数字供用户自行权衡；`full` 适合小库存重上下文场景，注意其 20 条折叠线。

## 五、复现方式

```bash
DSH_MEMORY_EVAL_VERBOSE=1 npx vitest run tests/recall-golden.spec.ts
```

verbose 输出包含每条查询的前 5 排名与命中详情；两张表（召回基线、注入成本）均由该命令打印，更新本报告时以最新运行为准。
