# Agent Note: memory_search 的零命中降级只落在工具层

Status: implemented

[English](2026-09-01-zero-hit-fallback-tool-layer.md) | 中文

## 问题

查询与任何条目没有共享词法 token 时,`memory_search` 返回空结果——模型无法区分「不存在这条记忆」与「你的用词不匹配」。两种读法都伤召回:模型要么换个措辞重搜(成本),要么认定记忆不存在而继续(注入面存在正是为了防的静默失败)。但朴素的「空时返回最近条目」会污染常驻注入面:开启 autoRecall 时每个 agent 步都会注入无关条目,破坏成本有界性和 `<memory-policy>` 里"记忆可能未加载"的诚实语义。

## 决策

降级只落在工具层,严格按改进计划的裁定:

- **触发条件。** 非空 `query` 且 BM25 结果为空(`total === 0`)。仅过滤器而无 query 的空调用是「过滤太窄」,不是「无匹配」——永不降级。
- **形态。** 同 scope/project/category 过滤器下最近的条目,在 output schema、render(「不是关键词命中」)与 presentation metadata 里显式标注 `fallback: true`;描述文案告诉模型把标注结果当作时间序上下文。
- **只读。** 降级路径只调 `store.list`——不盖召回戳、不递增 `accessCount`、不复活休眠条目。被降级曝光的休眠条目保持休眠;召回元数据纪律不受触碰。
- **其余一切严格词法。** 注入面(快照、索引、自动召回)与 remote 投影保持严格词法语义,永远看不到降级。

## 曾考虑的替代方案

- **降级做在 `MemoryStore.search` 内。** 否决:注入面与管理 UI 都消费该方法;store 层降级会把无关条目推进常驻 prompt,每次浏览也推进 UI。
- **降级并盖召回戳。** 否决:把查询没匹配到的条目呈现出来不是召回;盖章会把模型从未真正搜到的条目复活,污染 janitor 的新鲜度信号。
- **基于 embedding 的降级。** 超出范围:语义平面被宿主接缝裁定暂缓;词法降级是零依赖的止血方案。

## 后果

- 模型现在只能经 flag 区分两种空;render 为空 store 单独加一行(「无条目可降级」),空 store 不会伪装成时间序上下文。
- `maxSearchResults = 0`(不限)时降级会返回全库——与仓库 limit-0 约定一致,但选择不限的部署应知晓降级继承这个无界性。
- 降级遵守与查询相同的过滤器;被 scope/category 过滤器隐藏的条目不会经它重新进入。
