# Agent Note: 主题遗忘带安全护栏,规模自检,冲突检测残余记录在案

Status: implemented

[English](2026-09-01-forget-selfcheck-conflict-residual.md) | 中文

## 问题

计划的最后一波关闭三个缺口。按主题遗忘只能逐 id 删除——模型必须枚举它可能不知道的 id。store 的规模迁移触发条件(条目接近上限)只存在于文档。冲突检测器只标注重叠:大幅换述的纠错完全检不出,而计划的验收信号(「大幅换述的纠错能产出待审提案」)在零 LLM 词法平面上不可达。

## 决策

- **`memory_forget`**——模型工具,批量遗忘与某主题词法相关的所有条目(与 `memory_search` 同一 BM25 语义,含休眠条目)。安全护栏:严格布尔 `confirm` 门(absent 或 false 在任何搜索/写入前拒绝),**pinned 条目豁免**并经 `pinnedSkipped` 报告(pin 在其他一切语义里都是"永不遗忘"),**失控护栏**拒绝超过搜索上限一半的批量——一个宽泛的 token 不能删掉半库。每条删除保留独立的 remove 审计;描述强制先用 `memory_search` 预览。
- **`scale-trigger-selfcheck`**——store 在构造时发现介质以 ≥`entriesCap`×80% 的条目数打开即 warn 一次(上限在越线时截断;自检在接近时告警——记录的分工;多进程告警归 `cross-process-detect`)。经宿主 logger 通道每次进程告警一次;缺 logger 静默。
- **`conflict-resolution` 以部分结题收尾,记录在案。**人审模式的 `memory_replace` 路径已走建议队列(P1-2,既有行为)——「消解提案走建议队列」的一半已满足。换述的一半在零 LLM 词法平面上不可达:真正的换述纠错测得 ≈0.02 IDF 加权重叠,对 0.1 的 stale 线;把阈值降下来会让 上海/海南 类干扰对(≈0.06)越线。一条测试把残余钉住,注释明确它记录的是代价而非要保护的行为——语义平面落地时更新它必须是有意识的行为。

## 曾考虑的替代方案

- **memory_forget 不设上限。** 否决:大库上一个宽泛的 token 词会不可逆地删掉半库条目;上限把最坏情况从静默数据损失变成要求收窄过滤器的拒绝。
- **静默跳过 pinned 条目。** 考虑后改为显式上报:静默行为隐藏了发生过什么;`pinnedSkipped` 告诉模型意图属实时可以 unpin 后重跑。
- **降低 conflict 阈值以抓换述。** 否决:干扰对(上海/海南 ≈0.06)会越线——假冲突多于抓到的纠错,正是 `dedup-idf-weighting` note 记录的取舍。

## 后果

- 主题遗忘端到端可审计(逐条 remove 记录)、有界、尊重 pin;审计表自身有上限,非常大的批量应分次以保全轨迹。
- 规模自检只判介质的打开状态——运行期涨过告警线要等下次重启才浮现。这是启动建议,不是实时监控。
- 冲突残余现在是文档化的测试:换述缺口只在语义平面落地时闭合(被宿主接缝裁定暂缓),钉住测试强制那次更新是有意识的。
