> Execution-layer companion to [sqlite-backend-and-batch-consolidation](2026-09-04-sqlite-backend-and-batch-consolidation.md) (the decision record). The phases shipped 2026-09-05 (commits 4d8796a → 53831d4); this note records what was actually built, where, and how it is verified — the plan's step structure kept, its provisional values replaced by the shipped calibration.

## Problem

The parent proposal settled what to change and what to reject, but not where the changes land (which file, which symbol), in what commit order, or how each step is mechanically verified. Putting that into the parent note would have bloated the decision record as construction churned line numbers and calibration values; leaving it unwritten would have forced the implementer to re-derive every insertion point. This note was the execution layer: per-phase commit slices, insertion points (symbol-anchored; the original 2026-09-04 line-number snapshot drifted and symbol names were the stable index), where tests live, and what documentation moves with each change.

## Decision

Phases 1–3 shipped as six commits (plus the notes); each step below records the shipped fact.

### Phase 1: anchors + two-tier batch consolidation

**Step 1.1 — entry model + meta table** (commit 4d8796a, follow-up e6513d4):
- `src/types.ts`: `MemoryEntry` gained `anchors?: readonly string[]`, `status?: 'active' | 'superseded'`, `supersededBy?: MemoryId` (JSDoc states the defaults: active, no anchors, supersession terminal); `AddMemoryInput`/`UpdateMemoryInput` gained the anchors write face. `status`/`supersededBy` deliberately stayed OFF `UpdateMemoryInput` — only the integration seam flips status (the Step 1.3 `supersedeEntry` method), so a contradiction's status and its `supersededBy` always land atomically.
- `src/store/index.ts`: the zod entry schema mirrored the three optional fields; `memoryDomainSpec` gained the fourth `meta` table (`MemoryMetaRecord` = `{ key: 'consolidation' | 'medium' | 'schema', value?, updatedAt? }`, `zod.looseObject`, table keys carrying the subsystem-suffix convention like `consolidation:lastRun`); `DomainMemoryStore` takes the fourth table in its constructor (a no-default positional — every call site updated at compile time) and exposes `getMeta`/`setMeta` (failures booked as `meta-write`).
- Tests: `tests/store-contract.spec.ts` (field round trips + the meta table describe) and `tests/integration/composition.spec.ts` (a legacy medium opens zero-migration; new fields + unknown meta keys survive a read-write-back). TECH_DESIGN (bilingual) §6.1/§6.3 updated; table enumerations across README/SEQUENCE_DIAGRAMS corrected to four tables; sidecars re-recorded.

**Step 1.2 — extraction schema + prompt** (commit 8121a2b):
- `ParsedMemory` gained required `anchors: string[]` (empty = tag-free) and optional `projectName`; trailing `[anchors: a, b, c]` / `[project: name]` tags parsed right-to-left after category/summary (the stacking order makes anchors not-the-line-end when both ride one line); tag stripping precedes the scanContent gate; tag-free legacy input parses identically. The two extraction prompts gained the hard-token/repo-name rules; the NO-OP gate is unchanged. `storeMemories`/`suggestMemories` project precedence: tag wins, cwd falls back, non-project scopes drop it; an empty anchors array means absent (never stored as `[]`).
- Tests: `tests/extract.spec.ts` (13 new parse/precedence cases), `tests/fixtures/extract-golden.ts` (+6 golden cases, structurally asserting the new optional fields). The human-review queue deliberately does not carry anchors (`AddSuggestionInput` unchanged).

**Step 1.3 — the per-round consolidation tier** (commit 54f422f):
- New `src/review/consolidate.ts`: `selectConsolidationCandidates` over the bm25 primitives (`CONSOLIDATION_SIMILARITY_THRESHOLD = 0.2` ∨ shared anchors with `ANCHOR_DF_CAP = 2` — module constants, docstrings record why they are not Config knobs; `MAX_CANDIDATES_PER_CALL = 20` truncation guard); `CONSOLIDATE_SYSTEM_PROMPT` with the anti-over-merge rules; `parseConsolidateVerdicts` over `<cN> <action> [targetEntryId] [content]` with offer-list fail-closed to `new`; `applyConsolidation` applying the four actions (merge/update via `mergeContent` + `update`; conflict adds the fresh fact FIRST, then supersedes the target — no window where the old entry is hidden and the new fact missing — and records the flip in the batch's live view so a later verdict on the same target fails closed to a plain add).
- The supersede seam: `MemoryStore.supersedeEntry(id, supersededBy)` (abstract no-op) with the `DomainMemoryStore` implementation atomically writing status + `supersededBy` + the caller's annotation, idempotent, audited with source `'janitor'` (the `AuditSource` enum has no consolidation member).
- Orchestration: `storeMemories` splits into a shared normalization gate feeding the two-tier path and the legacy dedup+judge loop, selected by the review Config `consolidation` (default `'two-tier'`); zero consolidation calls on a no-candidate batch; the three extraction triggers forward the mode.
- Surfaces: standing snapshot, existence index, auto-recall, and `search` filter superseded; the tool surface keeps them visible with the `[superseded → <id>]` annotation and a structured field. Settings card: the consolidation select + en/zh locales.
- Tests: `tests/consolidate.spec.ts` (29 cases); the judge-path and corpus cases pin the `'legacy-judge'` switch with unchanged assertions; `tests/dedup.spec.ts` untouched and green.

**Step 1.4 — the periodic whole-store tier** (commit 6b83cd5):
- New `src/review/sweep.ts`: `rankForSweep` (hitCount DESC → accessCount DESC → last-use DESC; superseded/soft-decayed excluded; top-N cap), `selectSweepPairs` (existing-vs-existing pairs on the shared 0.2 lexical signal alone — the per-round selector's parsed-vs-stored shape does not transfer, and anchors add nothing on a usage-ranked set), `SWEEP_SYSTEM_PROMPT` + `buildSweepMessages` (the `p<N>` protocol), `parseSweepVerdicts` (pair-scoped targets; dropped verdicts fail closed to INACTION — nothing new exists to land, the opposite of the per-round `new`), `applySweep` (merge folds into the surviving target; conflict supersedes the target through the same seam with the annotation pointing at the survivor), `runSweepPass` (zero LLM calls on an empty pair set), and the cooldown pair (`sweepCooldownOpen`/`stampSweepLastRun` over the meta key `consolidation:lastRun`, ≥1 h between passes).
- Wiring: the review plugin's `session/created` listener runs the startup pass (first creation) and the per-N cadence (`sweepEveryNSessions` default 20), gated by `sweepEnabled` (default **false**) and the cooldown; the extraction budget deliberately does not bound the sweep. Config `sweepTopN` default 20. Settings card + en/zh locales.
- eval mechanical layer: `duplicatePairCount` in `eval/mechanical.ts` (verdicts beyond the first per planted fact; null judge-skipped), surfaced as `storage.duplicatePairs` in `eval/report.ts` slices (summed, not averaged).
- Tests: `tests/sweep.spec.ts` (25 cases incl. the zero-shared-anchor fixture — the en rate-limit pair, measured overlap 0.24); `tests/write-path-rework-acceptance.spec.ts` (5 cases: the prog101 contradiction → superseded + annotated, prog112 projectName + anchor pairing, the audited 9/2 duplicate-pair baseline reading 11 by the counter — the report's "10 pairs" prose counted the tracked fact set, the counter counts every extra verdict — and the corpus contract lint). TECH_DESIDE/plan-note fact layers updated with the shipped calibration.

### Phase 2: usage feedback (hitCount) — commit fca0861

- **Step 3.1 the backend:** `src/store/sqlite.ts` — `SqliteMemoryStore extends MemoryStore` over `DatabaseSync` in `$DSH_HOME/storages/memory.db` (WAL, `busy_timeout` 5 s); tables `entries` (`id` PRIMARY KEY, MemoryEntry columns), `audit`, `suggestions`, `meta`; booleans bind as 0/1, objects/arrays as JSON, NULL = absent; one statement per record with entries + audit in one transaction; search re-uses the full-corpus BM25 df discipline; `supersedeEntry`/`markHits`/janitor/trim mirror the domain store; `getMeta`/`setMeta`/`close()` complete the surface. CrossProcessGuard stays host-medium-only.

- Tests: `tests/migration.spec.ts` (the three transition states over the real composition + import fidelity); `runStoreContractSuite('SqliteMemoryStore', …)` runs the full 24-case contract body over a fresh mkdtemp database per case (73 contract tests green across the three backends).

## Alternatives considered

- **Folding the execution detail back into the parent proposal** — no. The parent note is a decision record and should stay stable around "what was decided"; execution detail churns as construction proceeds (line numbers drift, calibration results get back-filled). A separate document lets the parent note change only when a decision changes. The two notes cross-link, so either reader is one hop away.
- **Single-release big-bang** — no. The phases are independently shippable and revertible; this plan sliced commits by Step precisely to preserve that property — when a Step goes wrong, the rollback boundary is a commit, not a release. Six commits landed as planned.
- **Consolidation output as JSON-schema structured output** — no. Every LLM protocol in the repo is a line protocol (the judge's one word, the curator's `<id>:`, the consolidation's `<candidateId>`), and the host LLM channel has no structured-output mechanism — output is recovered as text through `collectStreamText`. A second protocol would mean a second parser and a second failure vector; the line protocol's fail-closed discipline was already covered by the dedup/extract specs.
- **Extending `findDuplicate` for cross-scope/anchor matching** — no. Its contract (same-scope near-duplicate detection, one threshold) is pinned by `tests/dedup.spec.ts`'s calibration pairs; extending it would re-couple pre-screening with completeness in one function. The selector is new code over the bm25 primitives; `dedup.ts` stays for the legacy kill switch.
- **The plan's Step 1.1 `status` write face on `UpdateMemoryInput`** — revised during Step 1.1: status/supersededBy deliberately stayed off the update input (only the integration seam flips an entry's status, so the annotation and the flip stay atomic); the shipped face is anchors-only.
- **The plan's Step 3.1 kernel-extraction commit** — revised during Step 3.1: unnecessary (the read logic was instance-private with no shared-state coupling; the bm25 module is the backend-neutral kernel), and skipping it deleted a whole commit of churn while the equivalence proof (contract green over both backends) stayed intact.
- **The plan's Step 3.2 settings-card select for `storage`** — revised during Step 3.2: the backend belongs to the `memory-store` composition row (`StoreConfig`), not the settings namespace — a provider swap is a composition concern, and cordis.patch.yml is the documented switch.
- **The migration marker read from the sqlite database's own meta table** — implementation bug caught by the migration spec's both-sides case: the marker lives in the MEDIUM's meta table (the migrating boot wrote it there); reading the sqlite side's table made the both-sides guard never fire. Shipped reading the medium's meta through the domain handle.
