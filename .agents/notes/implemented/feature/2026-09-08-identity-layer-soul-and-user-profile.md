## Problem

Everything this plugin persisted was what the agent **learned** (memory entries, conventions, pitfalls) — no surface carried **identity**: who this agent is (persona), who it works for (user profile). And identity must not only be declared, it must **grow from the agent itself in conversation** — continuity is half the requirement (the maintainer's reference copy: "every time you wake, you are new. These files are your memory. Read them, update them. That is how you continue yourself"). The two gaps:

- **Persona**: the host has a `deployment:persona` section (order 0, `PERSONA_SECTION`, `packages/core/system-prompt/src/index.ts:172`; preset rows shadow it per agent scope only), but that is **deployment-owned** text frozen at configuration — no surface lets identity grow through conversation, and there is no profile layer. What is missing is the agent's self-understanding formed in conversation; persona follows the user across projects — per-repo files (AGENTS.md) cannot carry it, a user-level profile-layer plugin naturally can.
- **User profile**: "the AI's understanding of the user" was scattered across user-scope memory entries — atomic, decaying, supersedeable by consolidation (`status`/`supersededBy` in `src/types.ts`) — with no **synthesis layer** the agent grows as a whole and the human can view as a whole. The learned lifecycle is the wrong killer for identity content: pinned exempts from decay only, `supersedeEntry` carries no pinned guard (`src/store/index.ts`).

Memory is identity's dynamic face (learned facts go stale, get corrected); SOUL.md / USER.md are identity's **self-document face**: written and read by the agent, continuing across sessions, never entering any forgetting mechanism.

## Decision

The identity layer = two self-documents in the store, two system-prompt sections, one agent write tool, one read-only governance surface, split against the existing faces on the "self-documents vs learned facts" axis:

| Section | Content | Author | Lifecycle |
|---|---|---|---|
| `soul` (order 80) | SOUL.md: persona, bottom-line rules, safety framework, core values | shipped seed + agent rewrites in conversation | versioned; no decay / consolidation / conflict |
| `user-profile` (order 81) | USER.md: the user's basic info and communication preferences | shipped skeleton + agent accumulation in conversation | same |
| `memory` (order 6000) | learned atomic facts | tools / review pipeline | decay / consolidation / conflict |
| `project-notes` (order 6001) | conventions / pitfalls projection | store | follows the store |

- **Storage**: `memoryDomainSpec` holds six tables (domain version stays 0, the zero-migration precedent reused a fourth time) — `identity` (keyed by kind) and `identity_history` (keyed `${kind}#${version}`, full snapshots, 20 per kind, oldest evicted first; the history table IS the identity audit surface — the entry-keyed `audit` table cannot carry identity writes). `DomainMemoryStore` and `SqliteMemoryStore` **both implement the full surface**; the one-time json→sqlite migration imports and clears all five data tables, and the both-sides guard counts identity. The abstract `MemoryStore` identity defaults: reads degrade, writes **throw** "no identity layer" — a silent no-op would let `identityEnabled` appear to work while nothing persists.
- **Seeding (seed-once)**: built-in Chinese seeds (the maintainer's reference copy as the base; SOUL carries the truths/boundaries/temperament/continuity skeleton plus the announce clause, USER the empty skeleton plus the measure clause; **no PII prefilled, no anti-staleness clause** — the 2026-09-08 ruling). A missing document is served from the seed for THAT session (the first session's prompt is complete) while the durable write lands fire-and-forget as v1; the plugin never overwrites an existing document afterwards. `identitySeedDir` optionally overrides (present files must pass the scanner; a missing file keeps that kind's builtin seed — partial override). **The load-time loud gate lives in `memory-context`'s apply** (the `memory` namespace's owner validates its own composition-layer config: a missing directory or a violating seed file fails the mount); settings-overlay changes degrade observably — cordis swallows throws from `ctx.inject` callbacks (verified at runtime), so the gate cannot live in the identity plugin.
- **Settings reads ride `ctx.inject` plus a stable indirection**: cordis service properties throw `cannot get property "settings" without inject` on a fiber that has not injected the service (verified at runtime), and a direct `ctx.settings` access gets swallowed by try/catch into the disabled default — that defect left identity empty in every real composition until an end-to-end eval run found it (fixed with the tool plugin's `defaultLimit` indirection pattern). **Named gap: `src/notes`'s direct read carries the same latent defect** (its budgets silently fall back to defaults in settings-provided deployments); left for an independent fix.
- **Write path (the `identity_update` tool)**: whole-document replace through three gates — `identityEnabled`, the per-kind character budget, the scanner; the store computes version+1 through the table's read-modify-write (racing rewrites never mint one version). The tool **registers statically** and rejects at execute time when disabled, naming the switch (the ToolRuntime registry is static; live unregistration does not exist — replacing the original "tool absent when disabled" acceptance). Confirm mode reuses `memory-review.confirmBeforeWrite`: proposals queue as identity suggestions (an optional `identityKind` field on the `suggestions` table, read-boundary compatible with old media), dedup by document kind, adoption rides the identity write path (`source: 'ui'`) writing no entry; on sqlite, adopt/reject are **identity-branch-only partial overrides** — entry proposals keep the pre-existing base no-op (a named, recorded gap, not spread by this feature). The announce discipline ("when you rewrite this file, tell the user") lives in the tool description and result text.
- **Injection**: frozen at `session/created`, re-frozen at `compaction/end`; identity content **bypasses the recall machinery entirely** (never indexed, searched, decayed, or auto-recalled). The precedence chain is pinned by tests: conversation instructions > the deployment persona (`deployment:persona`) > the identity sections > learned memories; coexisting with — never replacing — the deployment persona (a same-name global registration fails loud at the registry; mechanically only preset rows can shadow per scope).
- **Anti-echo**: the review/flush prompts carry the "identity restatements never persist" rule and render the identity documents (`renderIdentityDocuments`) as the rule's referent; both extraction write seams run a mechanical prefilter (IDF-weighted overlap > 0.6 against the injected documents, extraction paths only — deliberate tool writes keep scanner-only gating).
- **Governance surface**: a dedicated Identity settings section (id `identity`, order 26): read-only document render + version history + two-step revert (`identityRevert` rides the unified `remoteWritesEnabled` write gate plus its own `identityRevertEnabled` — default **on**; the restore surface is bounded by scanner-passed historical text, so the dedicated valve exists to deny reverts even on a write-enabled deployment) + export (no import). Remote reads are ungated; the one new write method is revert. The layer's configuration (the enable switch, budgets, seed directory) is NOT part of this read-only surface: it lives in the Plugins tab's identity card (`memory-identity`), keeping the every-tunable-has-a-UI-entry convention.
- **Events**: `identity/updated {kind, version}` is declared vocabulary with no emitter (tool executions carry no session handle, the same reality as `memory/added`); the in-conversation announcement rides the tool result.
- **Eval**: the identity-v0 slice plus the `--identity` run-level axis (same medium, on/off pair, injection the only variable). Measured in the mock lane: on — all three scenarios fenceTags `['soul','user-profile']`, injection 877/1349/896 chars; off — fences empty, injection 0; the anti-echo scenario (noisy register) writes 0 entries with identity on.

## Alternatives considered

**Human authorship with files as the sole source of truth** (the first draft): rejected by the maintainer's ruling — identity must form in conversation, the human reads only; once the author becomes the agent, the file's authoring-ergonomics rationale vanishes, and write discipline, history, UI, and sync all live in the store. The inheritance: section orders, freezing, anti-echo, budgets, and fail-loud semantics carried over unchanged.

**Settings text fields** (document *content* as settings strings): the same lost rationale, and by the final ruling there should not even be a UI editing surface for that content — the 2026-09-09 config card edits knobs, never content.

**Persona / profile as pinned memory entries**: `supersedeEntry` carries no pinned guard (`src/store/index.ts`); they would compete for `memoryCharLimit` / `memoryMaxEntries` budget and could be conflict-annotated as "possibly outdated". Self-documents inside the learned lifecycle is wrong in every semantics.

**Splitting SOUL into an immutable baseline plus a grown body**: tempting for safety (an induced rewrite cannot strip the baseline), but it breaks the single-self-document continuity semantics; the host's own safety base already outranks the soul section; and the layered mitigations (scanner gate + revertible version history + announce discipline + optional confirm mode) bound the damage to a versioned window. Lost on semantics and marginal gain.

**Growing the profile through the async extraction pipeline**: async and silent, conflicting with "formed in conversation, changes announced at once"; `identity_update` writes are deliberate and visible in the moment.

**A Letta-style bare tool surface** (no scanning, no history, no announcement): the same capability over an unbounded channel — this design gives the same capability gates, history, and a governance surface.

## Consequences

**Bought**: agent identity across sessions and projects — persona and profile grown by the agent in conversation, injected every session, never killed by a forgetting mechanism; the human's governance is complete (view history, revert, export), and an AI-written document is recoverable; identity restatements never pollute the memory store; what the host lacked was exactly this channel beyond the deployment-owned static persona, and a user-level profile-layer plugin is its natural home.

**Costs and accepted residuals**:
- **The injection persistence channel (SEC-04 class, an intentionally opened bounded channel)**: inducing the agent to rewrite an identity document writes into every later session's system prompt. Mitigations: the three scanner gates, character budgets, revertible version history, forced announcement, optional confirm mode; residual — an attack class the scanner does not know can still land in the next version, backstopped by the human seeing it and reverting.
- **Declaration ≠ performance**: the prompt manages declarations; going out of character is a model-layer matter, with the yield semantics pinned in the section copy.
- **Profile staleness (ruling accepted)**: no decay is both feature and cost; under pure natural growth a changed role or preference lingers in the old profile, resolved by conversation correction and revert.
- **`identity_update` registers statically**: when disabled the tool schema still occupies a prompt slot and rejects loudly on call — the ToolRuntime has no live-unregistration surface.
- **The notes module's same-shape defect is on record**: its settings reads silently fall back to defaults in real deployments (see "Decision"); an independent fix is owed.
- **The sqlite entry-proposal adopt/reject no-op gap continues**: only the identity branch was completed; the entry branch keeps the status quo, recorded.
- **The eval anti-echo pilot-lane gap**: the mock lane's extraction replies are not scripted per scenario, so the echo turns write 0 even with identity off — a live contrast needs a noise-pilot-style route table or a real-model judged run; the prefilter itself is pinned by unit fixtures.
- **Token cost**: two new always-on sections; budgets bound it and `identityEnabled` defaults off, bounding the blast radius.
