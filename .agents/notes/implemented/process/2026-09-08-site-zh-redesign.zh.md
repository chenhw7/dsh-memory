# Agent Note: 中文站点页面迁移到全新的明暗双主题设计系统

Status: implemented

[English](2026-09-08-site-zh-redesign.md) | 中文

## Problem

GitHub Pages 站点（仓库根目录的三个手写 HTML）存在两类结构性问题。其一是呈现：每页各自复制一份内联的「深色琥珀」主题，完全没有白天模式，也没有中文主页——`index.html` 只有英文，中文受众要从一门外语页面的导航链接进入站点。其二是事实：中文技术解析停留在 v0.9 写路径重构之前——声称三张持久化表（v0.9 起是四张）、存储只讲 `memory.json`（没有 SQLite 后端、没有写放大 A/B）、把整合预筛称作「Jaccard」（两层整合之后是 IDF 加权重叠）、且缺少 v0.9 条目字段（`summary` 已有；`anchors`、`status`/`supersededBy`、`hitCount` 没有）。仓库的门面在替产品说过期的话。

## Decision

中文两页在一套共享设计系统上从零重建，中文优先；英文页面在同一轮评审中跟进，用英文文案在同一系统上重建。

- **设计系统，四个站点页面共享：** `assets/site.css`（主题令牌 + 组件词汇）与 `assets/site.js`（主题切换接线 + 滚动显现 observer）。白天模式为纯白 + DeepSeek 品牌蓝 `#4D6BFE`；黑夜模式从同一色系派生（深夜蓝背景、提亮的主色）。主题行为：首访跟随 `prefers-color-scheme`，手动切换经 `localStorage('cairn-theme')` 持久化，每页 `<head>` 内联预载脚本在首绘前写好 `data-theme`（无闪烁）。字体：自托管**得意黑**做标题（维护者明确要求粗壮、拒绝纤细字体），正文 Noto Sans SC 500，数字与代码 IBM Plex Mono；新页面不再加载 Noto Serif SC。
- **`index.zh-CN.html`（新建）** —— 中文主页，完整产品页：Hero（「重启之后，它还记得。」）、无记忆 vs 有 Cairn 对比、四大能力卡、数字墙、三步工作原理、安全信任区、管理中心示意、诚实限制区、轻量**项目状态**条（npm registry 版本 + `stats.json` 累计；烘焙快照兜底，`?offline=1` 纯静态演示）、入口链接。
- **`memory-architecture.zh-CN.html`（重写，URL 不变）** —— 技术解析改为站点之旅「一条记忆的一生」：全景 → 诞生（捕获）→ 入库（写闸）→ 成长（整合）→ 召回（BM25）→ 注入 → 衰减 → 告别（遗忘/人审），外加尾声基准区；每站配「为什么这样设计」决策盒。事实对齐 v0.9.1：四张表、双后端与写放大 A/B、两层整合与 `supersededBy`、v0.9 条目字段、967 个测试用例。
- **`index.html` 与 `memory-architecture.html`（英文，同一轮评审中重建）** —— 与中文页相同的结构、演示和设计系统，英文文案；旧琥珀页——包括三路数据面板和烘焙的 `v0.8.0` 版本牌——被替换。两个 URL 均不变。
- **交互收敛为四个移植演示**（写入安全门——载荷 rAF 滑行、真实 BM25 演练场、注入模式切换器、衰减滑块）；提取模拟器、粒子 hero、环路动画、建议队列改为静态图解。
- **数字政策：** 页面上每个数字都有 CI 门禁或 Agent Note 记录背书（扫描器规则数对照 `src/scanner.ts` 清点；排序规则对照 `src/store/index.ts`；测试数取 2026-09-07 eval-workspace note）。部分完成的真模型判分切片（91.3%）刻意不引用。
- **周边：** `sitemap.xml` 载入全部四个页面并刷新 lastmod。`stats.json` 管线不动——两个主页只读消费。语言互链在各页导航内（主页与深度页均有中英切换）。

## Alternatives considered

- **把 `index.html` 原地改写成中文。** 否决：根 URL 今天就是英文站；原地替换等于在英文版重做被明确推迟的当下直接删掉英文主页。新增兄弟 URL 让两个受众都有门可入。
- **沿用现有页面的逐页内联样式。** 否决：两页共享同一令牌集，被推迟的英文版重建预期采用同一系统——设计令牌一个家，而不是第三、第四份会漂移的 CSS 副本。
- **移植全部七个演示。** 否决：四个招牌演示足以承载叙事；另外三个「重做外观 + 重测」只增加维护面积，不给页面论点加分。
- **主页只用静态数字。** 否决：烘焙的版本牌会在两次发布之间过期（英文页烘焙的 `v0.8.0` 就是活例子）；npm + stats.json 轻量通道加优雅烘焙兜底，几乎零成本地让状态条保持诚实。

## Consequences

- 四个站点页面共享同一设计系统；过渡期双皮肤状态随英文页在同一轮评审中重建而结束（2026-09-08）。
- `assets/fonts/SmileySans-Oblique.woff2` 给仓库增加约 1.4 MB 字体二进制。它以 SIL OFL 1.1 发布、许可证随包提交（`assets/fonts/SmileySans-OFL.txt`）；字体未做任何修改，保留字体名条款由此满足。
- 中文技术解析 URL 不变，所有入站链接与搜索索引引用继续有效。
- 每页加载 `assets/site.css` + `assets/site.js`；唯一携带语言的共享规则是衰减覆盖层，其文案由各页 `data-dead` 属性注入。
- 引用快速变动数字（测试数、版本号）的页面会随发布漂移，需要随版本刷新；既定决策是它们与发布在同一个变更里更新，与任何其他文档断言一视同仁。
- 主页最初的 pnpm 两幕对话小剧场在评审后移除（2026-09-08）：对话行继承了 flex 布局、句子被拆成离散片段，且维护者希望三步图解独立成段——`.dg`/`.msg` 样式随之删除。
- 技术解析页 hero 引导段居左（2026-09-08 评审后续）：`.hero-sub` 的 `margin: auto` 居中与 deep hero 的左对齐相抵，`body.deep .hero .hero-sub{margin-left:0}` 将其钉在标题左缘；两个语言版本共享该规则。
- 全站小字号落在 12/13/13.5/14px 阶梯（2026-09-08 评审后续）：IBM Plex Mono 600 在 ~13px 以下、Windows 100% 缩放（设备像素比 1）下会遭整像素 hinting 失真，故所有 9.5–13.5px 字号整体上抬一档——约等于 125% 缩放下的渲染效果。人审队列头部的 `.ms-head` 内联副本并入共享规则，搜索演示的 token 标签 11px → 12px。保留原字体不变是有意的：失真是小字号光栅化的产物，不是字体本身的性质（换字体、加 `text-rendering` 均被考虑后否决）。
